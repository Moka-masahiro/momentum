# モメンタム（自分用・日本株）

株AIアプリ「KabuAI」のプロモ動画を参考に作った、スマホ向けのアプリ。
**PC の電源は要らない。** 平日の夕方に GitHub Actions が全銘柄の日足を取り直して計算し、
暗号化したデータと画面を GitHub Pages に置く。スマホではそのページを開くだけで、
ホーム画面に追加すればアドレスバーの無いアプリとして開ける。

もとは Stock Advisor（`D:\AI作業場\stock-advisor`）のスマホ画面 `/m/` として作ったもので、
2026-09-27 に独立させた。計算の中身は同じで、Stock Advisor のサーバーや DB には依存しない。

```
平日 17:00（GitHub Actions）
  JPX の銘柄一覧（約3,700社）＋ yfinance の日足2年分 ＋ 日経平均
    → 指標・シグナル・検証を計算（pipeline/momentum）
    → 画面ごとのデータを gzip → AES-256-GCM で暗号化（web/public/data/*.bin）
    → 画面をビルドして GitHub Pages に公開
スマホ
  https://<ユーザー名>.github.io/<リポジトリ名>/ を開く → 合言葉で復号して表示
```

## 初回の準備（GitHub）

1. GitHub のアカウントを作る（無料。メールアドレスと2段階認証が必要）
2. 空の **Public** リポジトリを作る（例: `momentum`。README などは作らない）
   - 無料プランの GitHub Pages は公開リポジトリでしか使えない。公開されるのはコードだけで、
     株価のデータはリポジトリに入れない（Actions から Pages に直接置く）
3. このフォルダーを push する
4. リポジトリの Settings → Secrets and variables → Actions → New repository secret で
   **`MOMENTUM_PASSPHRASE`** に合言葉を入れる（12文字以上を推奨。他で使っているパスワードは使わない）
5. Settings → Pages → Build and deployment の Source を **GitHub Actions** にする
6. Actions → daily → Run workflow で1回目を手で動かす（約10分）
7. スマホで `https://<ユーザー名>.github.io/<リポジトリ名>/` を開き、合言葉を入れる。
   Chrome の「︙」→「アプリをインストール」でホーム画面に置く

## 毎日の動き

- 平日 17:00 JST に自動実行（`.github/workflows/daily.yml`）。GitHub の混雑で30分ほど遅れることがある
- 回帰テスト → 取得 → 計算 → 暗号化 → 画面のビルド → 公開、の順
- **取れた銘柄が9割未満、または最新の日足が6日より古ければ失敗にして公開しない。**
  壊れたデータで上書きせず、前日のデータが残る。失敗すると GitHub からメールが届く
- 実行記録を `pipeline/last_run.json` にコミットする。公開リポジトリは60日間変化が無いと
  定時実行が自動で止められるので、その対策も兼ねている
- 手で動かすときは Actions → daily → Run workflow

## 指標・シグナル・検証

計算の中身は Stock Advisor の README「スマホ画面『モメンタム』」の節と同じ。要点だけ書く。

- **モメンタム度（0〜100）**: 20・60・120日の騰落率を、その銘柄の普段の値動き（60日の日次σ）で割った
  z 値を合成したもの。ランク S ≥85 / A ≥70 / B ≥55 / C ≥40 / D <40
- 他に SR・POWER・買い集め・安定度・RSI、シグナル6種（買い集め・出来高急増・高値ブレイク・
  ランクS入り・押し目反発・トレンド崩れ）、月足・週足・日足の向きと節目の整理（ルールベース）
- シグナルの成績は「翌営業日の始値 → N営業日後の終値」を**同じ期間の市場平均との差**で測る

### 検証の結果（2026-09-27 時点、2024-12-20〜2026-08-25 の407営業日）

**6つの指標も6種類のシグナルも、その後のリターン（市場比）を統計的に有意には説明していない。**

| 指標 | IC 20日後（t値） | 前半（〜2025-09-24） | 後半 |
|---|---|---|---|
| モメンタム度 | +0.018（0.51） | −0.004 | +0.036 |
| 安定度 | +0.025（0.93） | +0.048 | +0.013 |

- モメンタム度は、期間の切り方で向きが変わる（1年分で測ったときは前半が正・後半が負だった）。
  直近60日の平均は −0.16 で、いまは強い銘柄ほどその後に市場平均に負けやすい局面
- 安定度だけは、どの期間で測っても「落ち着いている銘柄ほどやや良い」向きだった（有意ではない）
- ランク別の20日後の市場比: S −0.28% / A +0.19% / B −0.15% / C −0.36% / D −0.53%
- シグナルはどれも市場比がほぼ0か負、勝率（市場比）は41〜46%

**ランキングは「いま強い銘柄」の一覧で、「これから上がる銘柄」の予想ではない。**
アプリの検証画面は毎日計算し直すので、期間が延びれば数字は変わる。
結論の文面も固定では書かず、その日のデータから作っている（固定で書くと、データが変わったときに嘘になる）。

### 株価の段差の補正

毎回2年分を取り直すので、取得の合間の株式分割による段差（Stock Advisor で起きた）は無い。
それでも Yahoo のデータ自体に未調整の分割が残っていることがあり（しまむら 2026-02-18、光陽社 2026-03-02）、
スピンオフ（Hamee 2025-10-30）もあるので、値幅制限を手がかりに補正している（`pipeline/momentum/data.py`）。
ストップ高の比例配分が続いた翌日は値幅が4倍に拡大される、呼値の丸めがある、といった落とし穴も考慮済み。

## 暗号化（合言葉）

無料の GitHub Pages は誰でもアクセスできる。そのまま置くと、自分用のアプリが他人にも見え、
Yahoo Finance 由来の株価を誰でも見られる形で再配布することにもなる。そこで全データを暗号化して置く。

- 鍵 = PBKDF2-HMAC-SHA256(合言葉, salt, 600,000回)、中身 = gzip した JSON を AES-256-GCM で暗号化
- 復号はスマホのブラウザの中（Web Crypto）で行う。合言葉はどこにも送らない
- salt（`pipeline/crypto.json`）は秘密ではない。毎日同じものを使うので、スマホは鍵を一度作れば済む
- 公開されるもの: コード、`pipeline/last_run.json`（実行日時と銘柄数だけ）、ページの存在と
  データの大きさ・更新時刻。**株価や指標の中身は、合言葉を知らなければ読めない**
- 検索エンジンには載せない（`robots.txt` と `noindex`）
- 合言葉を変えるときは secret を書き換えて Run workflow。スマホは自動で入力画面に戻る
- 弱点: 合言葉が推測されやすいと意味が無い（総当たりは手元で何度でも試せる）。12文字以上の、
  他で使っていない文字列にすること

## ウォッチリスト

サーバーが無いので、**その端末のブラウザの中にだけ**保存する（外には送らない）。
PC とスマホでは別々のリストになる。設定画面から銘柄コードをまとめて貼り付けて登録できる。

## 率直なリスクと制約

- **Yahoo がクラウドからのアクセスを断ることがある**（HTTP 429）。取得は時間を置いて3回までやり直し、
  それでも9割に届かなければその日は公開しない。続くようなら方式を見直す（PC で取得して push する等）
- yfinance は非公式。仕様変更で突然取れなくなることがある
- JPX の銘柄一覧は置き場所や形式が変わる（2026-09 に `.xls` → `.xlsx` になり、古いURLは404になった）。
  一覧ページからその時点のリンクを探すようにしてある
- GitHub の定時実行は混雑時に遅れる・まれに飛ぶ。データ日付は画面の右上に出るので、古ければ気づける
- 価格はリアルタイムではない（前営業日までの日足）
- 検証は約2年分で、特定の相場局面に強く依存する。上場廃止銘柄が抜けている（生存者バイアス）

## 構成

```
pipeline/
  build.py            毎日の処理の入口（取得 → 計算 → 暗号化して書き出し）
  fetch.py            JPX の銘柄一覧・yfinance の日足と日経平均
  secure.py           暗号化（PBKDF2 + AES-GCM）
  crypto.json         salt（公開してよい）
  last_run.json       最後の実行記録（Actions がコミットする）
  momentum/           data（整形・段差補正）/ indicators / signals / report / validate /
                      compute（まとめて計算）/ export（画面用のデータに組み立て）
  tests/test_momentum.py
web/                  React + Vite + TypeScript + Tailwind + lightweight-charts
  src/data.ts         データの読み込みと復号・ランキングや検索の組み立て
  src/watch.ts        ウォッチリスト（端末の中に保存）
  src/components/Lock.tsx  合言葉の入力画面
  public/sw.js        Service Worker（アプリとして開く・電波が無くても前回の内容を見る）
.github/workflows/daily.yml
```

## 判断の記録

- **GitHub を選んだ理由**: PC なしで毎日計算を回すには、どこかのクラウドの計算資源が要る。
  無料で、アカウント以外の登録（クレジットカード等）が要らず、実行と公開が同じ場所で済む
- **毎回2年分を取り直す理由**: 差分だけ足すと分割の調整が取得時期ごとにずれる。取得時間は
  リクエストの回数で決まり、期間の長さではほとんど変わらない。2年分あれば検証期間を1年半取れる
- **データをリポジトリに入れない理由**: 毎日30MB近いデータをコミットすると、リポジトリが
  際限なく膨らむ。Pages には Actions から直接置ける
- **Stock Advisor の `/m/` は残してある**（家の Wi-Fi 内で使う版）。不要になったら消してよい
